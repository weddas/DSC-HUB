DSC catalog collation contract — one-pager for merge workers
Full doc: docs/qa/CATALOG-COLLATION-CONTRACT.md

LAYERS
  canonical  ← reviews / grow notes / lab chem / consensus grow
  variant    ← bank PDP claims
  observation/review/note/edge ← sourced append-only (never squash)

GROW NOTES
  Documents, not canonical fields. Keep each note.
  Hooks: canonical_id (name_norm), optional variant_id, source_id, date.
  Typed extract only when sure → also grow_trait with same source_id.
  Forums = note factories; bank PDPs = shorter higher-trust variant notes.

REVIEWS
  Store raw. Collate at read time. Wordcloud = derived projection (not SoT).
  Medauth for full CannaReviews. Lab chem ≠ review vibes.

LINEAGE
  Graph in entity_link (parent_of / child_of + source_id + unresolved literals).
  Mermaid is a view. Cross-ref queries must work on edges.

MERGE ORDER
  1) Match keys + trust ladder + conflict=keep both
  2) entity_link on every genetics parse
  3) observation/review ingest WITHOUT attribute_kv
  4) wordcloud builder later

DO NOT
  Squash notes; invent chem/grow; explode scores into attribute_kv;
  treat Mermaid or wordcloud as SoT; fight other exclusive merge holders.
