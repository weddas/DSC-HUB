### Heatmat first attempt exposed a driver bug (fixed + redeployed 16:57Z)

- 16:49:53Z demand ON → relay never showed true on `/fleet`; device online + pingable (10.42.0.51, 2–4 ms).
- Root cause in `brain/dsc_brain/appliance_driver.py`: `DEMAND_TO_SEAT` carries two heatmat aliases (`grow_mat_demand`, the real hub object_id, plus legacy `growmat_demand`). `_read_hub_demands` emitted **every** mapped oid, defaulting the undiscovered alias to False — so each ~2 s tick commanded heatmat ON then immediately OFF. `fleet_history` shows the relay physically chattering ON/OFF every ~10 s from 16:52–16:55Z until demand was dropped. Heater/humidifier were unaffected (single alias each).
- Fix: `_read_hub_demands` / `_demands_from_discovered` only report object_ids actually discovered on the hub. Deployed by syncing the file to `/opt/dsc-hub-repo/brain`, rebuilding `dsc-hub-brain:7.0.0`, and force-recreating the container (health OK 16:57Z). Post-fix history shows exactly one ON (16:58:01) and one OFF (16:58:41). Merged tip `67e08c5` / `ab49dd8` — see [`../brain/FLEET-INGEST.md`](../brain/FLEET-INGEST.md).
